# Архитектура и структура приложения: Системы счисления (Number Systems)

---

## 1. Общая картина

Приложение "Системы счисления" — это цифровой инструмент для быстрого перевода чисел и вычисления математических выражений между 6 системами счисления (двоичной, восьмеричной, десятеричной, шестнадцатеричной, римскими цифрами и еврейской гематрией). Приложение состоит из трех главных слоев: экранов интерфейса (UI), движка конвертации и расчетов (Logic) и моделей данных (Data).

**Аналогия из реальной жизни — Современный ресторан:**
Представьте приложение в виде ресторана:
- **Официанты (Экраны UI):** Принимают заказ у клиента (ввод числа или выражения) и презентуют готовые блюда во всплывающем окне.
- **Кухня и Шеф-повар (Движок конвертации):** Берет заказ, проверяет свежесть ингредиентов (валидация) и готовит результаты во всех форматах.
- **Тарелки и Меню (Модели данных и Адаптеры):** Удерживают данные аккуратно оформленными для удобного чтения.
Такое разделение предотвращает путаницу, поддерживает порядок и позволяет менять логику кухни без нарушения дизайна зала.

## 2. Обзор папок и файлов

Проект разделен на четкие пакеты и структуры:

### 📁 Главный пакет (`zeev.fraiman.numbersystems`)

- **Компоненты экранов (Activities & Fragments):**
  - `SplashActivity`: Загрузочный экран с логотипом на 4 секунды перед переходом на главный экран.
  - `MainActivity`: Главный экран-контейнер для вкладок.
  - `ConverterFragment`: Экран конвертера чисел ("All Types").
  - `CalculatorFragment`: Экран калькулятора выражений.

- **Компоненты интерфейса и диалогов (Adapters & Dialogs):**
  - `ViewPagerAdapter`: Адаптер вкладок для `ViewPager2`.
  - `CustomResultsDialog`: Кастомный нижний диалог (`BottomSheetDialog`) для вывода результатов.
  - `ResultsAdapter`: Адаптер RecyclerView с кнопкой копирования в буфер обмена.

- **Модели данных (Models & Enums):**
  - `NumeralSystem`: Enum с 6 поддерживаемыми системами счисления.
  - `ResultItem`: Модель данных пары (название системы + переведенное значение).
  - `ConversionResult`: Модель хранения результатов конвертации.
  - `CalculatorResult`: Модель хранения результатов вычислений.

- **Движок логики и конвертеров (Engine / Converters):**
  - `NumberConverter`: Центральный движок, переводящий любой ввод в десятеричное число (база 10) и из него — во все остальные системы.
  - `RomanConverter`: Движок парсинга и форматирования римских чисел (1–3999).
  - `GematriaConverter`: Движок парсинга и форматирования еврейской гематрии (1–3999).
  - `ExpressionEvaluator`: Вычислитель математических выражений (`+`, `-`, `*`).

### 📁 Каталог ресурсов (`res/`)
- `res/layout/`: XML-файлы разметки экранов, диалога и карточек.
- `res/values/strings.xml`: Файл текстовых строк и сообщений.
- `res/drawable/`: Картинка логотипа (`logo.png`).

## 3. Взаимосвязь между частями

Схема ниже иллюстрирует поток данных от ввода пользователя к отображению результата:

```
[Пользователь вводит данные и нажимает кнопку]
                │
                ▼
   [ConverterFragment / CalculatorFragment]
                │ (Первичная валидация)
                ▼
        [NumberConverter]  ◄──►  [RomanConverter / GematriaConverter]
                │ (Перевод в десятеричный IR и форматирование)
                ▼
   [ConversionResult / CalculatorResult]
                │ (Формирование списка ResultItem)
                ▼
      [CustomResultsDialog]  ──►  [ResultsAdapter]  ──►  [Карточки на экране]
```

**Пошаговый сценарий:**
1. Пользователь вводит значение в `ConverterFragment` и нажимает "All Types".
2. Фрагмент вызывает `NumberConverter.convertAll()`.
3. `NumberConverter` парсит ввод в промежуточное десятеричное число `long`.
4. Движок форматирует десятеричное значение во все 6 систем и возвращает `ConversionResult`.
5. Фрагмент формирует список `ResultItem` и открывает `CustomResultsDialog.show()`.
6. Диалог отображает карточки с результатами через `ResultsAdapter`.

## 4. Пример из проекта: Перевод римского числа

Сценарий, когда пользователь выбирает римскую систему, вводит `XII` и нажимает "All Types":

1. **Обработка нажатия в `ConverterFragment`:**
```java
private void performConversion() {
    String inputText = binding.etInputNumber.getText().toString(); // "XII"
    NumeralSystem selectedSystem = getSelectedSystem(); // ROMAN

    ConversionResult result = NumberConverter.convertAll(inputText, selectedSystem);
    // ...
}
```

2. **Парсинг в `NumberConverter` и `RomanConverter`:**
```java
// Внутри RomanConverter.java:
public static long parse(String input) {
    // Парсит "XII" в десятеричное число 12
    // Проверяет правильность записи и диапазон [1..3999]
    return 12;
}
```

3. **Конвертация и вывод результатов:**
```java
// Внутри NumberConverter.java:
for (NumeralSystem targetSystem : NumeralSystem.values()) {
    result.put(targetSystem, formatFromDecimal(12, targetSystem));
}
// Результат: BIN="1100", DEC="12", HEX="C", ROMAN="XII", GEMATRIA="י'"...

// Вызов диалога CustomResultsDialog:
CustomResultsDialog.show(requireContext(), "Results in all systems:", subtitle, items);
```

## 5. Краткий словарь терминов

- **Activity:** Главный экран или окно в Android-приложении.
- **Fragment:** Переиспользуемый независимый модуль интерфейса внутри Activity.
- **Adapter:** Компонент-мост, связывающий источник данных с элементами UI (RecyclerView).
- **View Binding:** Механизм прямого и безопасного доступа к элементам разметки из кода Java.
- **BottomSheetDialog:** Всплывающий снизу модальный диалог.
- **Enum:** Тип данных, определяющий фиксированный набор констант (6 систем счисления).
- **Intermediate Representation (IR):** Архитектурный шаблон, переводящий данные сначала в универсальную десятеричную базу для упрощения мультисистемной конвертации.
